# Router X 网络版本发布手册

这份文档用于后续把 Router X 发布成 GitHub 网络依赖，方便其他 Android 项目直接引用。

## 结论

- 推荐使用 JitPack 发布公开版本。
- Router X 需要发布三个模块：`core_router_annotation`、`core_router_api`、`core_router_processor`。
- 使用方通常只需要依赖 `core_router_api` 和 `core_router_processor`，不需要单独依赖 `core_router_annotation`。
- 每个写了路由注解的业务模块仍然需要配置 KSP 和唯一 `moduleName`。

## 当前发布配置

已配置文件：

```text
core/core_router_annotation/build.gradle
core/core_router_api/build.gradle
core/core_router_processor/build.gradle
jitpack.yml
core/路由版本发布.md
```

发布产物：

```text
core_router_annotation  JVM jar，包含 @Route、@Param、@ProvideService、@Interceptor 等注解
core_router_api         Android AAR，包含 Router 运行时 API 和 consumer 混淆规则
core_router_processor   JVM jar，KSP 处理器
```

## 发版前检查

每次发布前先执行：

```bash
./gradlew :core:core_router_annotation:compileKotlin :core:core_router_api:compileDebugKotlin :core:core_router_processor:compileKotlin
```

建议再验证本地 Maven 发布：

```bash
./gradlew :core:core_router_annotation:publishReleasePublicationToMavenLocal :core:core_router_api:publishReleasePublicationToMavenLocal :core:core_router_processor:publishReleasePublicationToMavenLocal "-PPOM_GROUP_ID=com.github.local" "-PPOM_VERSION=1.0.0"
```

Windows PowerShell：

```powershell
.\gradlew.bat :core:core_router_annotation:compileKotlin :core:core_router_api:compileDebugKotlin :core:core_router_processor:compileKotlin
.\gradlew.bat :core:core_router_annotation:publishReleasePublicationToMavenLocal :core:core_router_api:publishReleasePublicationToMavenLocal :core:core_router_processor:publishReleasePublicationToMavenLocal "-PPOM_GROUP_ID=com.github.local" "-PPOM_VERSION=1.0.0"
```

如果这两步失败，不要打 tag 发布。

## JitPack 发布

### 1. 提交代码

JitPack 只读取 GitHub 上的代码，本地未提交内容不会发布。

```bash
git status
git add .
git commit -m "release router 1.0.0"
git push origin master
```

### 2. 打版本 tag

```bash
git tag v1.0.0
git push origin v1.0.0
```

### 3. 到 JitPack 构建

打开：

```text
https://jitpack.io/#wukuiqing49/ApplicationArchitecture
```

输入 tag：

```text
v1.0.0
```

点击 `Get it`，等待构建成功。

## 使用方接入

### 1. 配置 JitPack 仓库

使用方项目的 `settings.gradle`：

```gradle
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories {
        google()
        mavenCentral()
        maven { url = "https://jitpack.io" }
    }
}
```

### 2. 配置 KSP 插件

根项目 `build.gradle`：

```gradle
plugins {
    id 'com.google.devtools.ksp' version '你的 Kotlin 对应 KSP 版本' apply false
}
```

### 3. 写了路由注解的模块

```gradle
plugins {
    id 'com.android.library'
    id 'org.jetbrains.kotlin.android'
    id 'com.google.devtools.ksp'
}

ksp {
    arg("moduleName", "FeatureHome")
}

dependencies {
    implementation "com.github.wukuiqing49.ApplicationArchitecture:core_router_api:v1.0.0"
    ksp "com.github.wukuiqing49.ApplicationArchitecture:core_router_processor:v1.0.0"
}
```

### 4. 只调用路由的模块

没有写 `@Route`、`@Param`、`@ProvideService`、`@Interceptor` 的模块，不需要 KSP：

```gradle
dependencies {
    implementation "com.github.wukuiqing49.ApplicationArchitecture:core_router_api:v1.0.0"
}
```

## moduleName 规则

需要配置：

```text
写了 @Route 的模块
写了 @Param 的模块
写了 @ProvideService 的模块
写了 @Interceptor 的模块
```

不需要配置：

```text
只调用 Router.init() 的 app 壳模块
只调用 Router.build() 跳转的模块
没有路由注解的工具模块
```

`moduleName` 必须在当前 App 内唯一。

## 混淆说明

`core_router_api` 已配置：

```gradle
consumerProguardFiles 'consumer-rules.pro'
```

使用方通过 JitPack 引用时，consumer rules 会随 AAR 传递。正常开启 R8 不需要每个业务项目再单独写一份 Router X 专属混淆规则。

## 当前限制

- 网络库接入仍然需要使用方手动配置 KSP 和 `moduleName`。
- `gradle/router-module.gradle` 只适合本项目源码依赖，不适合网络库引用。
- 后续可以做一个 Gradle 插件，让使用方只写：

```gradle
plugins {
    id 'com.wkq.router'
}

router {
    moduleName = "FeatureHome"
}
```

插件内部负责 apply KSP、配置 `moduleName`、添加 `core_router_api` 和 `core_router_processor` 依赖。
